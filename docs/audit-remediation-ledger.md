# Version 5 audit-remediation ledger

This ledger maps every workstream in the version 5 production-template audit
to repository evidence. The source audit is the
[start-ui-web template audit](https://claude.ai/code/artifact/7ccde1b1-abb2-4ec1-8c8d-def1f93af536),
as reconciled into the accepted v5 remediation plan. A row is closed only when
the implementation and its named verification evidence both exist.

Statuses have deliberately narrow meanings:

- `verified-fixed`: the implementation and a regression gate are present;
- `refuted`: repository evidence disproves the original claim;
- `superseded`: an accepted v5 decision replaces the audited behavior; and
- `open`: some required implementation or release evidence is still missing.

An expired review date or an alpha release does not change a row's status.
Final v5 release requires zero `open` rows. Until a final-release command owns
that policy, the normal PR gate validates the ledger's shape and evidence but
does not pretend the release is complete.

## Release use

Each remediation commit updates affected rows in the same commit. Evidence must
name a tracked implementation artifact and a deterministic test or gate; prose
alone cannot close a verified finding. A refutation or supersession must state
its rationale in the final column and link the accepted decision.

The alpha and beta pipelines may contain `open` rows. The eventual final-release
gate must invoke the ledger validator in zero-open mode alongside `pnpm verify`,
the release browser and service matrices, mutation ratchets, and Jittest.
